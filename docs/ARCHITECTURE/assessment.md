## 二、对照发布计划的就绪度

### 2.1 已知问题披露（dev-preview-release-plan.md ③）

数据层相关的已知问题应在开发者预览版说明中披露：

> **开发者预览版 — 已知限制**
> - 本地语义搜索（"80年代机战番"这类模糊查询）暂不可用——数据索引正在建设中
> - 如果未配置 Bangumi Access Token，部分功能（用户画像、日志分析、时光机）不可用
> - 深度模式下偶尔偷懒不查数据

### 2.2 限流（①）

**当前状态**：数据层没有客户端限流。API 层依赖 Bangumi 返回 429 后被动重试。**需要在 `main.py` 加限流中间件**（与数据层无关，但影响发布）。

### 2.3 数据收集（⑥ DEV_MODE telemetry）

**已就绪**。`DEV_MODE=true` 时，`/chat` 响应附带 `telemetry` 字段，包含：
- 每次 LLM 调用的 token 消耗
- 每个 graph 节点的耗时

**缺失**：数据库层无慢查询日志。建议加：
```python
# database/engine.py
echo_pool=True,  # 连接池事件（获取/归还/超时）
```

### 2.4 空搜索结果快速放弃（⑧）

建议在 `tools/bgm_tools.py` 中 `search_local_bangumi` 返回空结果时，注入提示让 LLM 不要反复搜：

```python
if not results:
    return (
        f"未找到与「{query}」相关的条目。"
        "建议：尝试使用更宽泛的关键词，或使用 search_bangumi_subject 进行关键词搜索。"
        "请勿对同一查询反复调用此工具。"
    )
```
当前代码已包含前两句，缺少"请勿反复调用"提示。

## 三、风险矩阵

### 3.1 发布前必须处理

| # | 风险 | 概率 | 影响 | 处理 |
|---|------|------|------|------|
| 1 | `search_local_bangumi` 对用户不可用 | **100%** | 中 | **在已知问题中明确标注** + 建议 LLM 优先用 API 搜索 |
| 2 | 无限流 → DeepSeek API 费用失控 | 中 | **高** | **加 IP 级限流中间件**（30 分钟工作量） |

### 3.2 发布前建议处理

| # | 风险 | 概率 | 影响 | 处理 |
|---|------|------|------|------|
| 3 | HNSW 索引失败 → 未来 RAG 性能差 | 低（表空） | 中（未来） | **短期可忽略**。在摄入数据前修复即可 |
| 4 | `pool_recycle` 缺失 → 偶尔连接断开 | 低 | 低 | 加 `pool_recycle=3600`（1 行改动） |
| 5 | v0/v1 RAG 共存 → 代码混乱 | 0% 对用户 | 低 | **开发者预览版不需要清理** |

### 3.3 可以推迟到公开预览版

| # | 风险 | 处理 |
|---|------|------|
| 6 | 无 Alembic 迁移版本管理 | 当前手动 DDL 足够可幂等。公开预览版时评估是否引入 |
| 7 | 硬编码值（超时、重试、截断等） | 不移入 config 不影响功能 |
| 8 | 死代码（`_ROLE_MAP`、`_TYPE_ICONS`、`_compute_cosine_distance`） | 清理是 nice-to-have |
| 9 | 工具错误前缀不一致 | LLM 不感知这种差异 |
| 10 | `get_episode_comments` 默认值不一致 | Pydantic Schema 优先，运行时行为正确 |
