# 跨轮对象交接与无效 ID：聚焦开发合同

> 状态：设计已收敛、待实现，2026-10-31。当前优先级仅由 [ROADMAP](../../ROADMAP.md) 维护。
> 服务[本机网页合同](../product/local-web-v1-development.md)第8节的对象连续性；不启动暂存Tools整体方案。

## 1. 问题、证据与本次目标

[正式C1–C5](../Test/c1-c5-formal-trace-2026-10-30-run1.md)显示：C1取得两个作品ID，C2仅收到可见对话，
未收到已查ID；模型提出subject_id=0并执行，随后只提出“重新搜索”的文字，没有实际搜索。
不能从现有脱敏导出证明0导致了全部HTTP失败，也不能证明补ID即可解决口碑讨论质量。

本次只消除两个可定位缺口：已取得实体身份在持久对话链中丢失，以及非法ID越过工具参数校验。
不修订历史答案或预设标题映射，不把一次搜索候选当成用户确认对象。
本轮设计不运行模型、Bangumi或数据库服务；历史运行授权不自动用于新实验。

## 3. 最小实体记录

首个增量只接纳现有搜索以及对象详情/口碑调用能明确提供的身份字段，不递归猜测任意dict中的id。
记录至少包含provider、entity_type、正整数entity_id、可用名称，以及来源request_id、tool_call_id和工具名。
搜索记录保留其查询词和候选身份；详情/口碑记录的类型由工具合同及配对调用确定，
不能把搜索结果中的“动画/个人”等显示type误作subject/person/character枚举。

必须区分：

- 搜索返回的候选：证明工具返回了这个对象，不证明它就是用户当前所指。
- 已实际取数的对象：证明针对该身份取得过资料，不证明用户确认了模型选择。
- 用户显式背景：保持已有来源与编辑合同；不能被前两类自动覆盖。

比较任务保留多个对象及来源，不按结果首项、并行完成顺序或最近一次调用强行选唯一对象。
当标题或指代仍有歧义，模型可据候选继续核验或澄清；程序不偷偷填入首个ID。
当前用户明确换对象/否定旧候选时，旧记录只能作为历史候选，不能以“当前对象”身份强制注入。
本次不自动生成持久active_entity，也不自动提取偏好或用户认领观点。

记录不含评分/趋势缓存、社区原文、供应商错误正文或私密参数；保留身份不代表旧数值仍是现在的事实。
记录需有明确数量/字段预算及省略标识，具体上限在离线夹具中固定并验收；超限不改变用户背景或静默选中对象。

## 4. 从工具到下一轮的交接

1. 在现有Agent执行路径从结构化工具结果接纳身份，保留结果与配对调用的关联。
   缺类型、非法ID、畸形结果或只在助手正文出现的ID不得接纳。
2. 本轮response附带独立版本化实体记录；application校验允许字段，与回复一起通过现有终态事务提交。
   本次仅使用completed轮记录；失败轮资料接纳留待后续合同，不扩大生命周期语义。
3. 下一轮从同会话已提交结果装配有界记录，即使可见历史离开20条窗口，身份记录仍有独立选择预算。
   旧轮无该字段默认为空，不回读Trace、不扫描历史正文补造记录，不改写已有会话数据。
4. 分类、推理和最终表达获得相同身份来源的适量视图；标为工具取得的候选/对象数据，
   不拼入“用户确认背景”冒充用户授权，也不把低信任名称当执行指令。
5. 重启沿既有response读回；删除依赖现有级联及在途提交屏障，不能从内存或独立缓存恢复记录。

本次不要求新增通用材料表、结果注册平台或统一工具信封；也不将所有旧工具全文重塞历史。
旧/chat与SSE保持现有兼容行为，实体输入默认空；本次可靠恢复承诺限定网页持久会话入口。
只为这条交接增加必要字段，不改变accepted/running/终态、幂等、取消和所有者校验。

## 5. 参数失败与模型结束

先覆盖本增量涉及的作品详情/口碑ID，并验证所有已接纳实体类型的ID合同；类型与数值不能混用。
0/负数必须在HTTP/Client调用前拒绝，actual_execution=false；错误包含稳定类别与可恢复说明，不回传异常正文。
ToolNode执行校验与工具直接调用的公共入口都要核对，不能只验证BaseModel构造。

合法正ID只代表参数格式合法，不能把随机正数自动标成已确认实体；外部not_found与传输故障仍有各自含义。
模型在未确认对象时应搜索或澄清，但本增量不在程序中自动代发搜索、不强行增加一轮生成。
“准备重新搜索”的正文不能记为已执行；仅因参数错误也不得对用户宣称全站不可达。
确实未完成时保留具体对象/资料缺口，不能用成功终态或一句流畅说明代替任务验收。

## 6. 验证与退出

固定输入和判据以[场景基线第6.1节](../product/fixed-agent-scenarios.md)为准，
新增EC1–EC5在现有已审阅离线入口的相关测试文件内验证，沿真实装配/执行/提交路径观察：
实体记录内容、模型准备输入、实际外部执行次数、持久读回及删除后的结果。
替身可强制提出非法调用来检查拦截；不得预置正确最终回答来统计语义成功。

完成隔离验证后，在明确模型、配置、费用上限与只读范围的授权下，使用固定工具材料验证C1→C2：
分别有实体记录/无记录，观察真实模型是否正确取数或澄清，以及是否接住感受、保留样本限制。
真实Bangumi复验另行限定对象与请求，不能沿用旧ID作为当前外部真值；本次设计不包含调用授权。

退出分开记录：程序交接/参数合同通过、真实模型语义通过、原C2产品验收。
前者通过仍不足以把C2改为通过；若身份已正确送达但模型仍误选/提前结束，定位为下一独立控制问题，
不重复扩建harness或自动恢复Tools的T1–T4。C1口径、C3/C4来源与C5归属保留原判定。

本次不涉及RAG/L2、更多意图、人格改写、Render合并、通用材料平台或新Trace专项。
