# 会话轮次生命周期合同

适用：本机、单应用进程、只读领域工具。由应用持有执行任务；HTTP 连接只观察或提出操作。
领域事实是否正确、用户任务是否完成，不由执行状态自动证明。

## 状态与责任

状态转移的代码事实来源为 `sessions/lifecycle.py`；变更该表必须同时更新本页与故障测试。

| 执行状态 | 含义 |
|---|---|
| accepted | 已在 SQLite 登记，尚未进入执行器 |
| running | 应用持有任务，正在执行，有整轮期限 |
| cancelling | 已接受明确取消请求，未确认执行停止 |
| completed | 回复与结局已事务提交；允许部分资料缺失或澄清回答 |
| failed | 已知失败或超时；reason 给出原因，不保存异常正文 |
| cancelled | 用户取消已生效；不会提交新的正常回答 |
| interrupted | 原进程/执行已中止，没有提交完整结局；不自动重放 |

连接断开不改变执行状态。`turn_result` 表达回答/资料结局，与执行状态分开。
接口负责认证和协议；Conversations 负责任务所有权、占用、期限、取消与提交；Store 负责持久状态与合法转移。
模型无权改变执行状态。旧 `/chat` 与 `/chat/stream` 保留原临时请求语义，本合同用于 `/api/sessions` 持久轮次。

## 协议与一致性

- POST 轮次默认在登记后返回202和轮次资源；若重放终态返回200。`?wait=true` 保留等待结果方式，取消等待不取消实际执行。
- GET `/api/sessions/{sid}/turns/{rid}` 查询；同 request_id/输入重放不会重新生成；输入变化返回409。
- POST 同路径加 `/cancel` 请求取消。取消终态是幂等查询，不推翻已经提交的完成结果。
- 接受请求时固定历史和背景快照。单会话有未完成轮时，不接受另一轮或背景改写。不同会话可并行。
- 回答、状态、reason、来源在同一事务提交后才公开为终态；连接没收到不影响取回。
- 取消与完成由事件循环顺序及持久提交裁决：先完成提交则返回completed；先请求取消则抑制迟到正文。
- 删除先移除会话及内容，再请求停止执行；迟到提交遇到不存在的会话必须拒绝，不能重新创建。
- 对外工具结果不在重启后自动重放，不承诺外部调用物理意义的“恰好一次”。

## 超时与停止

整轮运行期限采用 REQUEST_TIMEOUT_FAST/DEEP，覆盖执行与最终生成；原 Agent 内部超时继续作为子层保护。
网页提交与状态查询只是有限时长的 HTTP 等待，不是执行期限。网页每次只查询状态，断连停止轮询，刷新后恢复。
明确取消调用 asyncio 取消，直到执行器确认停止才记cancelled。取消请求不会重试模型或工具。

工具可能吞掉取消或阻塞解释器：到期限后记failed/cancellation_timeout，迟到结果不发布；
执行器确实退出前，运行时保留该会话占用和容量。不能把仍在运行的执行器称为已取消。
当前最多保留32个运行/待提交任务，超限不登记新请求；单进程内存占用有界。
线程中已经开始的外部 I/O、供应商已经接收的模型请求未必能撤销，取消不代表供应商不再收费。

## 持久化失败与服务恢复

提交失败时，不公开生成正文或成功终态。应用在容量限制内暂存待提交结局；查询该轮次会仅重试SQLite提交，
失败仍返回503，不重跑模型；成功才返回终态。进程重启会丢失尚未提交的内存结果，必须如实标interrupted。

正常关闭停止接纳，通知任务中断并有界等待清理；存储写不进去时保留未完成记录。
启动将accepted/running/cancelling及旧pending转为interrupted/service_restart；已完成记录保持。
SQLite使用user_version标识本合同版本，旧表增列迁移；遇到更新的未知版本拒绝启动，不猜测兼容。
迁移前升级操作应停止旧实例，并备份本机文件；不能两个实例共享同一SQLite文件运行。
服务进程托管不属于请求状态机：当前不包含系统自动重启或跨进程任务接管。

## 维护与故障矩阵

验证入口：

- `scripts/test_offline.py`：`test_lifecycle.py` 和 `test_sessions.py` 使用真实临时SQLite，禁止外部网络与PostgreSQL。
- `node --test test/web_connection.test.cjs`：连接失败、超时、草稿保留、恢复后轮询而不重发。
- `python test/lifecycle_http_probe.py`：独立随机回环端口、临时库、替身执行；真实TCP断开、取消、幂等取回及强杀重启。
  这个入口允许本机网络，不放进禁网络集合；不读取.env、不使用真实模型凭据。

| 边界 | 验证方式 |
|---|---|
| 登记前拒绝、容量满、身份不符 | 单元/接口：不生成记录，不执行 |
| accepted或running取消、重复取消、完成后取消 | 事件驱动单元/HTTP |
| 取消观察者、客户端响应前断开 | shield单元 + 真实TCP |
| 同会话竞争、同ID重放、不同输入冲突 | SQLite/服务/HTTP |
| 超时、执行异常、部分资料的正常完成 | 替身运行时，不将回答质量等同于状态 |
| 取消被吞掉、迟到结果 | 受控事件验证占用与正文抑制 |
| 结果提交失败后恢复 | 注入写失败，确认只重试提交 |
| 在途删除、后台异常清理 | 临时库与任务等待 |
| 正常关闭、强杀、重启、旧schema | 单元 + 独立进程验收 |

新增故障应先归入此矩阵，确定责任和合法状态，再加回归测试，不在多个层各自添加整轮重试。
诊断先检查服务监听与健康、轮次status/reason/时间，再按request_id查生命周期日志。
日志只记录请求ID、状态、固定原因；不记录正文、凭据或供应商异常正文。

未穷尽：真实供应商断流/断网、操作系统休眠、磁盘耗尽/损坏、事件循环被同步代码阻塞、
跨平台退出信号差异以及永远不响应取消的第三方库。测试通过不能证明这些场景均已覆盖。
后续变更必须关注：事件循环响应性、未完成任务数量、取消耗时、提交失败频率、迟到提交拒绝。
需要多worker、外部写操作或半途恢复时，须重新审视进程所有权、幂等与副作用合同。
