## 文档状态

- **产品基线**：PRODUCT；近期功能、人格和入口取舍以它为判断尺子。
- **开发规范**：AGENTS；架构细节由架构蓝图维护，使用方式由 README 维护。
- **当前状态**：ROADMAP；只留有执行入口和验收条件的待办。
- **参考手册**：memory、Rag、database-admin、eval 的说明；出现旧路径或旧指标须以代码重新核验。
- **产品方向**：愿景保留为长期方向；旧 Phase 7–9 路线仅供决策追溯，不作为排期。
- **历史档案**：design 中其余旧提案、AUDIT/REVIEW、docs/eval 方法论计划书；保留其当时的事实，不逐篇伪装更新。
- **数据产物**：不纳入文档清理，也不以历史评测数值代替当前测试。

“死台账”处理方式：当前清单移除已完成/失效条目，原因可在 ROADMAP 和 Git 历史追溯。
“死代码”处理方式：先核对调用、兼容入口和测试，再独立删除；本轮不连带删除 L3 兼容函数或旧实验资产。

## 引用检查

`scripts/check_doc_refs.py` 检查 Git 跟踪及未跟踪 Markdown 的链接和大小写。
被 `.gitignore` 明确排除的生成路径在本地和干净 CI checkout 中都只作提示；
没有忽略规则且不存在的活文档引用才会作为断链失败。
绿色只表示引用通过，不代表语义内容正确；指向未跟踪或忽略文件的引用会单独提示。
检查器的 LIVE_PREFIXES 定义严格检查范围，应与上述开发入口一致。

Git 中的目录拼写是 `docs/design`、`docs/eval`、`docs/memory`、`docs/Rag`。
macOS 磁盘可能显示不同大小写，链接必须按 Git 拼写。

## 本机资料边界

`docs/tmp/`、`docs/DEPRECATED/` 被忽略，不属于 clone 后可得的资料。
面向他人的说明必须放入受版本管理的目录。
UserScript 参考文件只在本机，使用另一套 /generate 协议；不算已发布客户端。

旧 O-/R- 前缀没有经过确认的统一定义，暂不推广这种命名。
后续每项决策优先写一段“问题—选择—验收”，避免再增加重复总览或未经核验的完成台账。
