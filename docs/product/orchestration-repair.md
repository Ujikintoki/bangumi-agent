> 不作为 Phase 台账或长期 backlog。

## 问题

已确认的三条连续对话场景暴露出同一类工程缺口：HTTP Render 不能可靠识别“本轮”产物，
推理异常和工具空结果没有显式结局，社区材料缺少足够的作者、定位与样本元数据。因此系统可能
复用历史正文、把失败话术当事实再次扩写，或在引用社区内容时无法说明来源边界。

## 选择与边界

- 在现有单 Agent graph 内增加小而确定的本轮结果契约；不重写拓扑，不增加多 Agent。
- 程序负责本轮边界、成功/部分成功/空结果/失败和来源元数据；模型只负责基于该契约组织表达。
- 在工具边界记录脱敏的工具名、参数键、成功状态、耗时与错误类型；不记录凭据、异常正文或完整用户材料。
- comments、reviews、board 分区必须明确；本轮只补已选场景所需读取链，不扩成全 endpoint 实现。
- 不建设 Web、写操作、收藏、排班、长期画像或人格专项优化。

架构四问：改动属于编排/状态与数据来源板块；接口位于 graph state → HTTP Render 交接和
Bangumi client sanitizer 边界；依赖方向保持 orchestration → persona/memory/data；对应架构演化图中的
可观测性与可靠执行，不增加新的板块。
