# 第一版本机网页：开发设计

> 状态：实施基线，2026-10-29；下述为实施契约；实际覆盖以 ROADMAP 和验收记录为准。
> 产品范围由 [PRODUCT](../../PRODUCT.md) 定义；顺序由 [ROADMAP](../../ROADMAP.md) 维护。
> 本文只维护技术契约、实现落点和验收，不复制路线图或累计完成记录。
> 2026-10-30范围校准：本轮以第8节的Web＋后端完整使用链路为退出条件；只实施其必要修复。
> Agent架构延伸见[暂存记录](agent-exploration-hold-2026-10-30.md)，不自动成为本轮前置工程。

## 1. 要解决的问题与首批可运行结果

已有后端可以接收聊天和组织工具，但用户仍需自行组合启动、调用和会话管理；
对象、纠正及证据在分类、推理和最终表达之间也不稳定。
第一版把现有能力组织成可返回的本机作品讨论，不以全面 core 重写作为网页开工条件。

首批代码必须让用户启动实例、打开同源网页、发送一条消息，经现有 Agent 获得回复或安全失败。
使用真实 HTTP/Agent 路径；隔离验证可以替换模型和工具，不用固定成功文案冒充业务实现。
先接 JSON，随后完善会话和上下文；逐 token 流、工具原始结果面板不阻塞首次可用。

## 2. 依据与不外推的结论

- [系统盘点](../codebase-inventory-report.md)：单进程互斥可复用；没有完整持久历史；正常启动强制数据库；工具异常可冒充数据。
- [Agent 盘点](../agent-design-inventory-report.md)：分类缺前文、部分分支工具不足、摘要到 Render 丢证据、纠正随窗口丢失。
- [OtakuNeko 研究](otakuneko-capability-study.md)：借鉴配置、对象附件、会话和可见进度的产品组织。
  当前参考提交为 [b595f03](https://github.com/ShowayLiao/OtakuNeko/tree/b595f03239f380aa2f534eab18022eecb78302e6)。
  该提交聊天页未传 thread_id、聊天请求未带登录凭据，前端删除也未联动后端记忆；
  有会话 UI 不等于持久恢复/删除已闭环。模型连接检查也不证明工具协议兼容。

以上证据支持局部改造，不证明简单循环优于当前所有分支，也不证明应该直接删除 Render。
两轮离线入口因 tokenizer 缓存缺失未运行测试；固定探针不提供真实任务成功率。

## 3. 首版工程默认

| 项目 | 采用的默认及边界 |
|---|---|
| 运行 | 单人本机、单应用进程；启动默认绑定回环地址。不将匿名模式暴露到局域网/公网；保留已有 Bearer 合同 |
| 网页 | FastAPI 同源提供轻量 HTML/CSS/JavaScript；首批不新增 Node 构建要求。框架选择不得改变下面的会话合同 |
| 模型配置 | 首批沿用环境变量/本机配置来源；网页显示缺项和就绪状态，不回传密钥或任意供应商错误正文。网页写密钥、多供应商管理不进首批 |
| 基础持久化 | 新增独立本地 SQLite 会话存储，记录用户可见历史、活动上下文与选中依据；与 PostgreSQL 向量表分开，不迁移/替换旧库 |
| 可选能力 | 本机基础模式关闭自动 L2，未配置本地 RAG 时不注册该工具；不得暗中尝试 embedding 或连接 PostgreSQL |
| Agent | 首批沿用 LangGraph、现有工具和人格；先修工具错误/证据交接和能力缺口。core 简化按第 7 节验证 |
| 保存期限 | 默认本机保留至用户删除；网页说明保存位置与范围。容量限制触发明确提示，不静默丢弃旧历史；自动清理/备份同步暂缓 |

SQLite 是新会话存储的实施默认，不是把现有 PostgreSQL schema 改成双数据库兼容层。
基础模式已按开关延迟加载旧数据库及 L2；可选依赖的全功能质量仍须分别验证。
可选能力显式开启时才初始化其资源；初始化失败应说明受影响能力，不把故障伪装成空检索。

## 4. 职责与调用路径

```text
同源网页：输入、对象/材料展示、会话操作、回复/依据/失败展示
    ↓ HTTP
整轮应用编排：身份、会话读取、占用、上下文装配、执行、提交与响应
    ├─ 会话存储模块：本地事实来源、事务、版本和删除
    └─ Agent：理解任务、按需工具使用、形成回答
         ├─ 人格与模型视图：行为约束、证据/历史预算
         └─ 工具 → HTTP 客户端 / 显式开启的本地检索
```

网页不提交助手历史作为后端事实来源；持久历史与模型工作窗口分开。
L1 可缓存模型所需视图，但不能成为唯一恢复来源；L2 不承担会话恢复。
新增会话模块不导入 AgentState、graph 或 HTTP 入口；应用编排负责转换数据。
对话执行可注入模型/工具替身，存储使用真实临时文件验证；不为假想后端增加通用适配框架。

对应蓝图开工四问：本次涉及编排、上下文/记忆、工具/人格及验证板块；HTTP 调用会话与 Agent，
下层不反向依赖编排；新增的是客户端交互与会话持久化位置，复用蓝图的页面语境/上下文方向。
后续真实修改系统接口时同步[架构蓝图](../architecture-blueprint.md)，不把此目标图冒充现状。

### 4.1 目录与依赖约定

目标是让行为有明确归属、调用方向可检查、安装环境可重建。以下是本次开发采用的目标布局，
不是当前目录已整理完成的声明；只在实际需要时创建目录，不预建空层或逐文件增加转发包装。

```text
main.py          应用入口与组装，保留现有 main:app 启动方式
api/             HTTP 路由、请求/响应模型、协议转换
application/     整轮对话编排：占用、装配、执行、提交与取消
sessions/        会话数据模型、历史/上下文管理、本地存储
web/             同源 HTML/CSS/JavaScript，按页面职责组织
agent/           图、节点、模型上下文、人格与推理期记忆
tools/           Agent 可调用的领域操作及结构化结果
clients/         外部 HTTP/SDK 访问与上游数据清洗
rag/             可选本地检索
database/        现有 PostgreSQL/向量模型及迁移
schemas/         现有共享领域/工具输入模型
core/            配置、安全及多模块共用的基础能力
test/            沿用当前测试入口，按行为/模块分组
scripts/         安装、验证、维护入口，不承载业务规则
docs/            按文档地图维护产品、设计与证据
```

HTTP 模型归 api，会话模型归 sessions，工具输入和共享领域模型沿用 schemas；
不因都使用 Pydantic 就集中为一个巨型模型文件。sessions 内的 SQLite 实现与历史管理先保持内聚，
不为尚不存在的第二种存储建立 repository/service/adapter 多层空壳。
主入口中的业务行为逐项移到实际拥有它的模块，不新增第二套平行的对话编排。
根目录保留入口、项目元数据与权威文档；运行数据库、日志和缓存使用明确的本机数据目录并排除版本管理，
不能混入源码、测试材料或受保护语料目录。

**允许的依赖方向**：

```text
main（组装依赖） → api → application → agent → tools → clients / rag / database
                                └──→ sessions → 本地存储
上述模块 → 必要的 core / 共享数据模型
```

- api 负责 HTTP 语义；application 负责整轮行为，不导入 FastAPI 请求/响应类型。
- agent 不导入 api、application、sessions 的存储实现或 main；所需会话上下文由 application 传入。
- sessions、人格、记忆及数据层不反向导入 AgentState、graph 或 HTTP；共享数据不得绑定上层运行状态。
- core 与共享模型不反向依赖业务模块；不要用局部导入或 TYPE_CHECKING 掩盖职责上的循环依赖。
- 模型工厂等现有横切能力按职责对待；若下层需引用目前位于 agent 内的横切实现，随该改动移至 core，
  同时处理旧导入兼容，不因此搬走整个人格/记忆目录。
- 外部客户端、存储与模型在应用组装/显式初始化时提供；导入模块不得联网、连接数据库、迁移或读取业务数据。
  可选能力关闭时，基础路径也不应因导入其 SDK 或全局单例而失败。

**第三方依赖与可复现安装**：

- 目标采用 pyproject.toml 作为直接依赖及可选组的唯一手工声明来源，uv.lock 锁定解析结果。
  如保留 requirements.txt 兼容安装，则从同一声明导出，不并行手工维护两套清单；这些文件的迁移尚未实施。
- 分开基础运行、PostgreSQL/RAG/L2 等可选能力、测试/检查工具；分组以真实导入路径为准。
  拆分必须同时解除导入耦合，不能只移动依赖清单里的条目。
- 直接使用的包必须显式声明，包括实际启用路径上的迁移工具和供应商 SDK；不能依赖传递安装或作者本机环境。
- 新增包说明服务的具体任务、为何标准库/现有包不够、属于哪个组；不为本次轻量网页顺带引入前端工具链。
- 不将缓存、模型数据、系统数据库扩展伪装成 Python 包依赖；按所选运行模式单独说明准备方式。
- 在可丢弃环境按锁安装基础组、再分别验证启用的可选组；记录支持的 Python 版本和运行条件。
  不趁依赖整理批量升级框架，不读取本机凭据，不用真实库验安装。

**落实与检查**：先为首批新增行为按上表落位，再随每个功能迁移其涉及的旧实现。
移动或替换前证明引用与兼容责任，变更后核对导入、动态注册、测试、启动命令、打包资源及文档链接。
验证应覆盖导入无外部访问、基础模式不要求可选 SDK、干净安装及相关用户行为；
不为每个目录增加只检查文件存在的测试，也不把目录数量当作规范程度。
当前接口归属由本文指导实施，实际变更后写回架构蓝图；推进状态只在 ROADMAP 维护。

## 5. 最小数据与 HTTP 合同

以下为拟新增/扩展的合同；现有 /chat、/chat/stream 调用方保持兼容，不移除原响应字段。

| 对象 | 最小内容与不变量 |
|---|---|
| 会话 | 服务端生成 ID、内部归属、标题、更新时间、版本；本机单用户不要求注册，已有认证身份仍由服务端绑定 |
| 可见轮次 | request_id、用户输入、最终回答、执行状态、时间；失败/中断单列，不混成成功助手回复 |
| 活动上下文 | 实体类型/ID/名称、主动材料、明确纠正/立场、会话内偏好、观看进度/剧透范围；每项可追溯到输入轮次并可修正 |
| 所选依据 | 类型、实体归属、出处/定位、取得时间、所用片段、样本/截断与失败维度；不默认持久保存所有工具原始响应 |

实体名称、链接和材料身份先分清：受支持 Bangumi URL 确定性解析类型/ID；名称歧义返回候选或澄清；
任意外链仅作为未读取链接，不能假装已读正文。粘贴内容标明用户陈述或引用，不将引文升级为用户偏好。
显式选择和明确纠正优先于旧推断；模型提出的上下文变更有来源、可见可撤销，不静默固化猜测。

拟新增会话创建/列表、读取、删除与上下文更新操作；服务端校验归属及版本。
扩展聊天请求承载 request_id 和主动对象/材料；执行前读回服务端上下文，防止只把前端新字段静默忽略。
重放相同 request_id 返回已有结局或处理中状态，不自动再次调用工具。
网页先显示等待、回复、具体失败和依据；后续公开进度事件使用调用 ID，并区分执行结束与资料成功。

具体执行状态、取消/超时/连接恢复合同与长期维护矩阵见[轮次生命周期](../Architecture/turn-lifecycle.md)。

### 提交、恢复与删除

1. 用户输入先记录为 pending；整轮取得占用后执行，保留现有同会话冲突处理。
2. 回答、结局、上下文变更与所选依据作为同一已完成轮事务提交，再交付最终成功响应。
   保存失败不得向网页宣称已保存；已生成但未送达的回复通过 request_id 查询，避免重复生成。
3. 重启后 pending 标记 interrupted，可供用户重新发起；不自动重放模型/工具，不恢复图中间节点。
4. 删除移除本机会话的正文、材料、依据、上下文并清除缓存；以版本或等价删除标识拒绝在途提交。
   最小删除标识不保留正文；浏览器内视图随之移除，不再另存一份独立长期历史。
5. 基础模式不写 L2，避免被删除内容后台写回；旧 L2 数据、用户导出文件或外部备份不在此删除操作内，界面准确说明。

## 6. 修改落点与验证接口

| 现有位置 / 拟新增位置 | 本次职责 | 验证行为 |
|---|---|---|
| main.py、core/config.py、core/auth.py | 本机启动/同源入口、就绪反馈、会话整轮接线；按需初始化可选资源 | 缺模型配置仍可进入页面；基础模式对 PostgreSQL/embedding 零访问；认证兼容 |
| 新增 web、api、application、sessions 模块（按第 4.1 节落位） | 输入/会话操作与本地事务；业务事实不依赖浏览器重传 | 刷新/重启恢复、两会话隔离、重复提交、删除与在途完成竞争 |
| agent/guardrails.py、tools/bgm_tools.py、main.py 的结果处理 | 工具边界结构化失败、畸形结果拒绝作为证据、合成秘密不进回复/日志/下一模型请求 | 抛错、空、部分数据、全通道失败各自有不同结局 |
| agent/nodes/classify.py、agent/nodes/pipeline.py、agent/prompts/tool_config.py | 分类获得必要上下文；实际任务/实体的工具能力不被单标签误封锁 | 同一句配不同对象；人物/角色详情；评分+趋势+前作比较 |
| agent/memory/short_term.py、main.py 的上下文装配 | 保持明确纠正和所选材料；模型窗口与完整历史分离 | 长历史后仍保留剧透范围/立场；SystemMessage 与工具调用配对保持有效 |
| main.py、agent/persona/render.py、agent/prompts/aggregator.py | 缺口/反证/用户立场进入最终回答；引用与截断一致；检查人格功能冲突 | 原评作者/定位正确，摘要不冒充全文，comment 不改用户立场 |

每个改动绑定上表中的行为，不顺带清理未证明无引用的代码。
会话存储相关测试使用临时 SQLite；已有 PostgreSQL 迁移保持原状，不能用会话开发授权连接真实库。

## 7. core 简化的方向与替换门槛

默认方向是上下文充分的单 Agent 主循环，程序承担工具范围、预算、状态、来源和失败合同。
分类可作为辅助判断，不能独占能力选择；固定 Pipeline 只有能减少遗漏/费用时才值得保留。
人格继续约束行为，取数硬限制与证据身份不靠人格文字实现。

独立 Render 倾向减少交接，但首批保留；不能先删再用回归失败证明需要补 prompt。
以同一对象、相同工具材料和用户纠正，对照当前路径与简化路径的对象/事实/立场/引用忠实性、
完成维度、调用数量、耗时和费用。改善目标明确且关键行为不退步后，才切换默认。
先用替身验证协议和数据，再经费用授权用真实模型验证行为；没有真实对照时不宣称简化质量更优。
这项对照不阻塞网页、会话和已确认错误的实现；不新增 Critic、L3 或多 Agent。

## 8. 验收与停止条件

| 场景 | 应观察的结果 |
|---|---|
| 首次进入 | 可丢弃环境按说明安装/启动；网页可达，配置错误定位清楚，基本任务不要求 RAG/L2 |
| 查询与比较 | 名称/链接定位对象；评分、趋势、前作各自取得或标为缺失，不互相代替 |
| 感受与纠正 | “我说的是演出，不是剧情；只看到第 3 集”在继续讨论、长历史及重启后仍有效 |
| 原评讨论 | 选一条可定位原评，保留作者、出处和范围；review 摘要不冒充全文，board 缺失只影响相关请求 |
| 按需轻内容 | “把我的观点整理成短 comment”保留立场与限定；允许无需新取数，内容可复制编辑 |
| 返回与隔离 | 两个作品会话不串；刷新和重启能找回已完成轮、上下文和所选依据；旧数值注明取得时间 |
| 失败与删除 | 空/失败/未执行可区分；取消/异常释放占用；删除后在途完成不能恢复正文；重复请求不重复执行 |

离线回归使用 scripts/test_offline.py，先在独立准备步骤备好 tokenizer 缓存；不擅自扩大测试集。
修正旧评测认证和生产材料视角后再复用其测量，不将 HTTP 200 或固定模型正确输出算任务通过。
真实模型、Bangumi 只读 API、下载依赖及隔离服务启动按各自授权和条件执行；不读 .env 或受保护数据，
不接真实 PostgreSQL 5432。缺少条件应报告具体未验项，不继续以假结果包装交付。

完成条件是上述真实使用链路和必要故障行为有对应证据，运行方法与已验证配置进入 README。
不要求追踪、完整 board、跨设备或长期偏好完成；也不因发现这些缺口继续扩大本次范围。
