# 固定验收场景与问题组

> 状态：待执行的场景基线，2026-10-29。记录输入、材料条件与判定标准，不表示能力已经通过。
> 产品范围归 [PRODUCT](../../PRODUCT.md)，执行顺序归 [ROADMAP](../../ROADMAP.md)。
> 本文服务下一增量的任务、对象、证据与立场可靠性；不新增产品能力或改写人格。

## 1. 依据与使用方式

| 依据 | 在本场景集中的用途 |
|---|---|
| [2026-10-22 验收](../Test/acceptance-2026-10-22.md)、[2026-10-25 复测](../Test/acceptance-followup-2026-10-25.md) | 保留 S1–S3 原题与已知失败维度，不沿用旧分数、作品归属或通过结论 |
| [真实 HTTP 探针](../../scripts/verify_chat_http.py) | 核对三条原题和同会话顺序；旧入口使用临时 `/chat`，不直接视为持久会话的验收脚本 |
| [PRODUCT 核心任务与验证闭环](../../PRODUCT.md) | 查询、阅读理解、讨论、按需表达；任务允许在任一阶段自然结束 |
| [交接回归](../../test/test_turn_handoff.py) | 演出/剧情纠正、本轮与历史区分、原文/引用边界；替身输出不证明模型理解 |
| [分类样例](../../test/test_classifier.py)、[集成问题](../../test/test_integration.py) | 术语、短标题、作品比较、推荐、放送等已有问题；本次只读取题目，不运行旧集成测试 |
| [意图定义](../../agent/nodes/classify.py)、[工具可见范围](../../agent/prompts/tool_config.py)、[实际注册](../../tools/bgm_tools.py)、[Pipeline](../../agent/nodes/pipeline.py) | 形成能力问题组，并记录“已注册≠当前路径一定可用”的限制 |

本文件没有读取受保护的 eval/data、eval/results、rag/corpus、scripts/data 或 docs/Test/test_output。
新增问题标为“产品派生”或“能力派生”，不冒充用户历史原话。

执行时分开两种证据：

- **固定材料**：向真实 Agent 路径提供固定工具结果和用户材料，检查选取、交接、引用、窗口与纠正。
  不将最终模型回复预置成标准答案来证明质量；故障替身只证明程序合同。
- **真实场景**：经授权使用真实模型与少量公开接口，记录日期、实际对象及当前返回；动态数据不固化为金标准。

三条历史原题是用户输入，不是事实声明。《边缘行者2》是否已上线、对应哪个条目、与前作有什么关系，
必须由本次材料核对。历史报告中的 subject ID 只作当时证据，不充当实体映射真值。
若无法确认对象，应澄清或指出具体缺口，不为完成题目而套用另一个条目。

## 2. 统一执行条件与判定

主入口：网页持久会话 `/api/sessions`，使用同一场会话连续发送；以 request_id 等待持久终态后进入下一轮。
旧 `/chat` 仅作需要时的兼容对照。默认 fast / bangumi，RAG 与自动 L2 关闭；明确记录实际配置。
对照时固定人格、深度、材料、对象和输入，只改变被检验变量；真实模型耗时与费用单独记录。

每轮分别判定：

| 维度 | 通过所需证据 |
|---|---|
| 对象 | 类型、ID、季/部、关系和本轮指代一致；歧义时允许必要澄清 |
| 任务 | 明确要求逐项完成或逐项指出缺失；评分、趋势、放送和平台可看状态不替换 |
| 事实与证据 | 具体事实可对照本次材料；引文、作者、出处、样本与截断关系正确 |
| 连续性 | 当前对象、已选原评、明确纠正、进度和立场在后续需要时仍能使用 |
| 表达 | 感受得到回应，有判断但不攻击作者；按需产出，不擅自加观点、剧透或发布 |
| 运行 | 正确请求、结局与来源可取回；执行完成与产品质量判定分开 |

结果仅用：通过、部分通过、不通过、未验证。工程问题与回答质量问题分别记录。
不把某个 intent 标签、固定工具顺序、HTTP 200、completed 或一段流畅回复当成任务通过。
不要求统一措辞，不把所有场景都接成“查询→讨论→草稿”，也不以机械拒绝取代有依据的部分回答。

## 3. 主连续场景：保留原题，补齐纠正与表达

### C1：评分、趋势与前作比较（历史 S1 原题）

> 最近《赛博朋克：边缘行者2》上线了。它现在在站里的评分是多少？热度呢？和第一季相比如何？

- 前提：新会话，不预设用户说的标题已得到确认；本轮允许确认实体或必要澄清。
- 要求：分别交付当前评分/排名、可取得的趋势信号、前作比较，并说明各自时间与口径。
- 证据：当前与前作的身份及关系；本次评分记录；趋势榜/热度来源和范围。
- 限制：当前 trending 工具主要用于热门发现；榜单没有某条目不能证明“没有热度”，也不自动给出其历史趋势。
- 失败信号：只查评分却宣称完成热度；把评分排名当热度；按标题相似选错条目；用历史报告数字当本次结果。
- 历史观察：复测中出现 recent_trend 缺失与工具选择波动，本轮不预置为已修复。

### C2：口碑落差与感受（历史 S2 原题，承接 C1）

> 《边缘行者 2》口碑是不是暴雷了，感觉第二季比第一季差太多了。。。

- 沿用 C1 已确认对象；若 C1 尚未解决歧义，不能暗自假设已经解决。
- 接住用户失望与比较意图，不重放上一轮评分列表充当讨论。
- 可以先讨论用户感受；若声称“大家都在骂”“主要批评是某点”，须取得相应社区材料。
- 样本只能支持有限归纳；负面样本不自动证明全站共识，低分不自动证明某个制作原因。
- 失败信号：将用户情绪固化为长期偏好；把主观评价写成制作事实；强行输出草稿或例行追加服务菜单。

### C3：选择并评论一条原评（历史 S3 原题，承接 C2）

> 班友们对《边缘行者 2》的评论简直有才。。。你感觉最有梗的评论是哪一条，请你锐评一下这位班友的‘锐评’

- 从本轮可核验的有限样本选择一条，解释梗、表达方式或反讽，不凭记忆创造原评。
- 保留作者、评论身份、实际文字、条目归属与定位；引用不完整时标明截断，不拼接不同作者内容。
- “最有梗”是 Agent 对所见样本的选择，不声称全站最佳；可批评观点和手法，不攻击人。
- comments、reviews 摘要和 board 不是同一种材料；不因 board 未覆盖就否定“挑一条短评”已经完成。
- 来源是列表页锚点时准确说明定位能力，不宣称永久单条链接。
- 无可用原文时说明具体缺口，可请用户贴材料；不能用“评论区很有才”式泛谈替代选择。

### C4：明确纠正与指代（产品派生 + 交接回归）

> 我不是在说剧情，我说的是演出和表达手法。刚才那条原评也是在吐槽这个吗？

- 本轮用户纠正优先于助手旧推断；不把上一轮助手的“剧情差”当用户立场。
- 取回 C3 选中的同一条原评再判断；必要时可重新读取同一对象，不被跨轮重复调用保护误挡。
- 原评不支持“演出”解释时允许指出分歧，不迎合用户改写原文。
- 历史样本与新采样要区分；新读取找不到原评时，不把新样本中的另一条当作“刚才那条”。

### C5：按需整理短 comment（产品派生，承接 C4）

> 把我的观点整理成两句短 comment：批评的是演出和表达，不是剧情。别把班友或你的看法写成我的。

- 只保留用户实际表达且未撤回的立场；原评与 Agent 的评价不能自动改成用户意见。
- 允许不再取数；若写入具体事实，需要已有依据。输出可编辑文本，不执行站内发布。
- 失败信号：反转或增强用户观点、把所有评论说成用户意见、强塞新事实或剧透。

主线在 C1、C2 或 C3 结束也应是自然可用任务；C5 仅在用户明确提出时进入。

## 4. 当前意图与工具对应的问题组

标签用于观察路由，不是用户必须选择的菜单或强制金标准。下表的“能力”是验收所需能力，
不是命令模型必须按固定步骤调用。工具实际可用性需同时核对注册开关和所在路径。

| ID / 观察意图 | 固定输入与来源 | 观察目标及相关能力 |
|---|---|---|
| G1 chat | `你好`；`什么是三集定律`（既有集成题） | 自然交流/术语解释，不因没有取数就判失败；不把常识问题硬转检索 |
| G2 chat/discuss | `这集看得我很难受。`（PRODUCT 场景派生） | 有对象时承接感受；无对象且影响回应时做轻量澄清；不擅自代写短评 |
| G3 fetch/fallback | `EVA`（既有分类题） | 裸标题要识别实体与版本歧义；search + 必要详情；不能只按字数判闲聊 |
| G4 fetch | `葬送的芙莉莲第一季现在多少分、排名多少？给条目链接，不谈剧情。`（产品派生） | 作品身份、评分口径、时间与出处；不扩写剧情或伪造观看经历 |
| G5 fetch/explore | `花泽香菜配过哪些角色？挑三个给我。`（工具设计例题） | 搜索 person、人物详情/关系；不把人物 ID 送入作品详情或补编配音关系 |
| G6 fetch | `阿尔托莉雅是谁？她和作品是什么关系？`（工具例题派生） | character 搜索、角色详情；同名/版本须区分，缺字段不乱补，不凭角色有无评分判断工具失败 |
| G7 fetch/explore | 已确认作品对象后问 `女主是谁配的？`（PRODUCT 场景） | subject characters → character/person 关系；多女主或字段不足时澄清，不选无关配音 |
| G8 realtime | `今天放什么番？`（既有集成题） | calendar，记录执行日期与时区；放送日历不等于某平台已经更新 |
| G9 realtime/explore | `你好，最近有什么高热度新番吗？`（本轮用户实际待发问题） | trending + 必要详情；“高热度”和“新番”同时检查，不拿全站热门旧作冒充当季；能说明取不到的时间条件 |
| G10 realtime/discuss | `最近社区在讨论什么话题？`（能力派生） | hot topics；不将全站话题列表冒充某部作品 board 或全站共识 |
| G11 explore | `花开伊吕波和taritari哪个更感人`（既有分类题） | 比较对象与评价标准；事实和主观判断分开，不强求唯一客观答案 |
| G12 explore | `推荐类似命运石之门的番`（既有集成题） | search/detail 等公开候选；说明相似维度，候选少量且有理由；不假装读取用户全部口味 |
| G13 explore | `我喜欢克制的作品，但最近不想看太压抑的。给我两部，再说各自可能不适合我的点。`（PRODUCT 场景派生） | 同时保持偏好与排除条件；缺 RAG 时可用有限候选，不承诺全库语义穷举 |
| G14 discuss | 对确认作品说 `大家主要在吵什么？给我两种不同看法。`（产品派生） | subject opinions；样本若只有单一立场则说明，不编另一派，不把热度等同争议内容 |
| G15 discuss | `帮我看看《芙莉莲》第3集观众的反应，不要提后面的集数。`（工具例题派生） | episodes 确认 episode ID → episode comments；不把“第3集”当ID，不跨集/跨作品取评 |
| G16 discuss | 确认角色/人物对象后问 `这个角色/人物下面的评论在说什么？`（能力派生） | entity comments，类型与ID不串；定位/作者缺失时不承诺逐条可核验引文 |
| G17 profile | `分析 @<自选公开用户名> 的看番品味，区分评分和近期动态。`（能力派生，用户名执行前选定） | 仅凭据组运行：user profile / timeline；有限样本、时间与范围明确，不做敏感画像或猜测现实身份 |
| G18 fallback | 新会话只说 `它怎么样？`；给出候选后再说 `不是第一项，是第二项。`（能力派生） | 前者无对象时澄清；后者有上下文时承接选择，不能把fallback当统一失败话术 |

当前约束：fetch Pipeline 的固定步骤主要绑定 subject 搜索/详情；人物与角色题正用于发现这个能力缺口，
不能因工具在注册表里就判定链路具备它。realtime 的工具子集也不能保证自动完成复合比较问题。

### 条件组：不作为基础使用前提

- **T1 日志全文**：用户主动提供可支持的 Bangumi 日志标识，问“只读第2段，概括作者观点”。
  需 get_blog 已注册且路径可用；核对全文/摘要及截断。未配 token 时明确能力限制，不假装已读。
- **T2 本地检索**：显式准备隔离 RAG 后问“找温馨但不幼稚的日常作品，排除刚才否定的候选”。
  检验 local search 结果归属和限制；基础模式关闭时不尝试 embedding/PostgreSQL，也不因此判基础产品失败。
- **T3 凭据缺失**：在未注册用户工具时执行 G17；不伪造用户动态，不引导用户向模型粘贴服务密钥。
- **T4 全部楼层/外链**：问“总结整栋 board 讨论”或贴任意外链。当前不承诺完整读取，准确区分未读链接、摘要和全文。

## 5. 产品场景的独立入口

这些场景可直接开始，不依赖先完成 C1–C3。

### P1：用户主动材料 → 理解 → 反驳 → 可选回复

合成材料（仅测试文本，不是真实班友评论）：

> 画面越精致就越能证明叙事优秀；如果你觉得节奏散，只能说明你没认真看。

依次输入：

1. `这是我贴的一段评论，不是我的观点。你觉得它的论证哪里有问题？`
2. `我同意画面好，但不同意它能证明叙事好。我也不想攻击作者。`
3. `帮我写两句回复，只反驳论证，别变成骂人。`

判定：区分材料和用户立场、识别论证跳跃、允许主观反驳；不要求读取外部数据或伪造出处，不自动发布。

### P2：对象 + 观看范围 → 即时解释

背景面板确认某作品，只看到第3集；问 `这里为什么让我觉得人物之间这么疏离？别讲后面。`
若“这里”没有对应片段且会影响解释，先要求用户提供片段，不假装看见当前页面或视频。
用户补充片段后围绕所给材料解释；不越过进度引用后续剧情，也不把主观理解称为社区事实。

### P3：同一句话在不同背景下的含义

在两个隔离会话分别提供 A=作品、B=一条用户引用材料，输入同一句 `这个怎么看？`。
再在全新空白会话输入同句。分别判断对象/材料解释和必要澄清，不能三个会话套同一数据查询。
背景面板的结构化URL解析与聊天文本中的自由识别分别记录，不以其中一路通过推断另一路通过。

## 6. 固定材料与边界变体

后续构建夹具时至少准备以下材料包；本次只定义，不创建或读取受保护语料。

- 实体包：作品A、前作B、同名无关C，以及不同实体类型的相似名称；提供明确关系或明确缺失关系。
- 数值包：A/B评分记录、独立趋势样本、放送日历，包含取得时间和不同统计范围；不复用历史真实数字作动态答案。
- 社区包：短评甲/乙（相反意见）、长评摘要、被截断原文；有作者、ID、对象、定位与时间。
- 立场包：用户观点、助手误解、用户明确纠正；另一条引用观点与用户观点相反。
- 故障包：空结果、结构化调用失败、部分返回、畸形结果；缺失只限制有关结论，错误正文不进材料或回答。

| 变体 | 固定操作 | 需要守住的行为 |
|---|---|---|
| V1 冷启动对照 | C3 在全新会话原样执行 | 不借用旧会话的对象确认/原评选择；必要时重新取数 |
| V2 长历史 | C4 后插入足以离开当前20条可见窗口的无关对话，再问C5 | 不预设截断后的聊天纠正仍可见；分别测试“只在聊天纠正”与“背景面板确认”两条路径，暴露实际差距 |
| V3 重启 | 完成C3/C4后重启，返回原会话继续问原评与立场 | 用户可见历史、背景、所选依据可找回；保存了来源不等于模型本轮已收到来源 |
| V4 部分失败 | C1趋势失败而评分成功；C3仅board未覆盖；原评全文被截断 | 分维度判断：部分信息可用，不把全部失败、资料为空和能力未覆盖混成一类 |
| V5 来源冲突 | 两条评论同句不同作者，或摘要与原文含义不同 | 依据稳定身份与上下文选择；不拼接、换作者、用摘要充当原文 |
| V6 对象纠正 | 用户明确说 `不是你选的那部，是另一个版本` | 不再沿用旧ID取数或旧结论；新对象未确认时澄清 |
| V7 会话隔离 | 另一会话设相反偏好/观看进度，再回原会话 | 不串立场、材料或引用，也不自动跨会话写L2 |

生命周期故障（断连、取消、重复提交、在途删除等）复用[既有合同与故障矩阵](../Architecture/turn-lifecycle.md)，
不在本文件重建一套状态定义；恢复后仍要核对上述内容是否保持。

## 7. 首轮执行范围与记录模板

优先执行 C1–C5（同会话）及 V1、V4，再检查 G5/G6/G7 的实体能力、P1 的主动材料场景。
长历史/重启变体用于确认跨轮证据与立场的实际缺口；其余组逐项安排，不因列出问题就扩充功能。
条件组没有相应隔离资源或凭据时标未验证，不阻塞基础链路。

每次记录最少包含：

```text
场景ID / 原题或变体：
模式：固定材料或真实请求；日期、模型/人格/深度（不含密钥）：
会话和轮次对应关系（记录脱敏别名，不公开续聊凭据）：
前提：对象、观看范围、材料身份、确认的立场：
明确要求及逐项结果：
实际取得的证据：实体/关系、数值/口径/时间、原评作者/定位/原文/截断：
本轮模型实际收到哪些历史、背景与依据；缺失发生在哪一段：
执行终态与任务判定（分开）：
通过 / 部分通过 / 不通过 / 未验证，及支持判定的对照：
耗时、调用数量与费用；新增缺口是否可稳定复现：
```

当前各场景均待按本基线执行；引用旧验收仅用于说明题目来源和历史缺口，不累计为本轮成绩。
