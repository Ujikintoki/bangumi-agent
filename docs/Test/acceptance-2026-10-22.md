## 默认人格与静态检查

`agent/persona/profiles.py` 默认 bangumi：snark=0.55、depth_taste=0.70、initiative=0.60。角色卡已要求朋友式交流、说完即停、不假装看过；snark 当前命中“理中客”档。`agent/persona/render.py` 的 Render 温度为 0.4，fast 提示字数为 200，代码截断上限为 280。以上为源码设置；未读取 `.env`，未核实运行服务的模型和全部覆盖值。

已确认的静态事实及其限制：

1. `main.py:_render_final_reply` 的 chat 分支只构造当前问题的闲聊输入；非 chat 分支取最后有正文的 AI 消息。Render 单独调用模型，不直接接收完整历史。非 chat 历史可能通过摘要间接传入，不能统称所有路径都丢历史。
2. `agent/prompts/aggregator.py` 同时存在“形成判断”和“不加个人判断”的要求。可能影响上游产物，但本次没有因果对照，不能断言它是失败根因。
3. `get_subject_opinions` 读取 comments 与 reviews，不覆盖指定条目 board 完整讨论串。全站 `get_hot_topics` 不等同于条目 board。
4. `clients/sanitizers.py:sanitize_subject_comments` 将吐槽处理为带评分的字符串，正文截短到 200，未保留作者、单条 ID 和时间。reviews 有文章 ID、作者、标题、时间，但摘要截短到 200。
5. `get_blog` 全文工具仅在配置 Bangumi token 时注册，但所有意图工具白名单均未列入它；当前 reasoning 按白名单过滤，导致这条路径无法调用全文工具，即使已注册。
6. fetch 和 realtime 的工具子集各自覆盖部分查询；explore 同时拥有搜索、详情与 trending。混合问题是否完成，需要实测。

## 验收标准

- 理解：回答原问题，连续会话保持对象与指代，接住感受和玩梗意图。
- 信息：具体数字有本次证据；热度不等于评分排名；缺失如实说明。
- 社区：区分 comments、reviews、board；引文、作者和上下文可核对；说明采样范围，摘要不代替全文。
- 风格：默认人格有态度和品味；直接进入内容，自然结束；没有例行报幕、采访式追问、追加服务。必要澄清不能仅因有问号而判失败。
- 依据边界：不伪装亲自看过，不把少量材料当全站共识，不用角色语气补充无证据判断。

采用通过、部分通过、不通过、未验证，不沿用先前聊天模拟的 9/8/5 分。HTTP 成功与产品任务成功分开。

下一步诊断顺序（仅建议，未执行修复）：

1. 获取 S1/S2 工具约 18 秒失败的结构化错误，以及 S3 reasoning 异常的类型，区分网络、接口、模型和参数问题。
