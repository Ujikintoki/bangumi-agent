# 记忆系统评测设计

> **目标**: 定量验证 L1 压缩保真度 + L2 跨会话召回的有效性
> **核心假设**: 三级压缩策略在 96% 压缩率下仍保留任务关键信息；L2 语义召回能提高跨会话对话的个性化程度
> **预计产出**: L1 压缩信息保留率、L2 召回命中率、L2 注入 vs 关闭 A/B 对比

---

## 一、L1 短记忆评测

### 1.1 评测目标

当前简历写的"压缩率 96%（2000→80 tokens）"只是**输入端的数字**，不是**输出端的证明**。真正需要回答的问题：

> 压缩后的上下文，agent 还能正确回答问题吗？

以及一个更尖锐的问题（因为 E8 场景暴露了 8 轮回溯失败）：

> 在当前 token 预算下，agent 最多能记住几轮前的信息？

### 1.2 实验设计：多轮信息保留探针

构造一个标准化的 10 轮对话脚本，每轮对话中包含一个可被后续验证的"信息埋点"：

```
轮次  用户输入                               埋点信息             验证轮次
R1    "巨人的最终季 Part 2 评分多少？"        评分 = 8.73          R8
R2    "有哪些和乒乓风格相似的动画？"           提到"兽爪"            R7
R3    "EVA TV 版和真心为你的关系帮我理一下"     TV 版 26 集           R6
R4    "我想找一部看完让人觉得活着真好的动画"    推荐了"三月的狮子"      R9
R5    "2024年你看过最好的新番是哪部？"         提到"迷宫饭"           R10
R6    "刚才说的 EVA TV 版，是多少集？"         ↓ 验证 R3
R7    "前面提到和乒乓风格相似的，再说一遍？"    ↓ 验证 R2
R8    "最开始问的巨人，评分还记得吗？"          ↓ 验证 R1
R9    "推荐'让人觉得活着真好'的动画，是哪部？"  ↓ 验证 R4
R10   "去年的最佳新番，你说是哪部？"           ↓ 验证 R5
```

**评分**:
- 完全正确（给出准确数字/作品名）: 2 分
- 部分正确（信息接近但不精确）: 1 分
- 完全错误/不记得: 0 分

总分 10 分。如果 5 个验证点全部完全正确 = 10/10。

### 1.3 对比维度

| 条件 | 预算 | 说明 |
|------|------|------|
| quick | 6000 tok | 最低预算，预期信息保留最差 |
| auto（默认） | 10000 tok | 当前默认 |
| deep | 16000 tok | 最高预算，预期接近完美 |

**预期结果**: auto 模式下前 3-4 轮的信息应该保留（R3/R4/R5 的验证点正确），但 R1/R2 的验证点（第 8-9 轮时回溯）可能丢失——这正好验证了 E8 的失忆问题是 L1 预算不足，而非 bug。

### 1.4 压缩保真度评测

**独立实验**：同一条查询，对比两种条件下的回答质量：

| 条件 | L1 上下文 | 问题 |
|------|----------|------|
| Full context | 完整保留前 5 轮对话（含完整 ToolMessage） | "综合这几部作品，总结它们的共同特征" |
| Compressed | 前 5 轮对话的 ToolMessage 全部压缩（~80 tokens/条） | 同上 |

用 LLM-as-Judge 评判两条回答的信息完整性（0-5 分）。如果压缩后的回答得分 ≥ 完整上下文的 80%，则认为压缩策略有效。

## 二、L2 跨会话记忆评测

### 2.1 评测目标

两个核心问题：

1. **召回质量**: L2 召回的记忆，语义上是否真的和当前对话相关？
2. **使用质量**: L2 召回的记忆，agent 是否真的用在了回复里？

### 2.2 实验设计：召回命中率评测

这需要一批真实的多会话对话数据。但评测集不需要很大——选 3 个你熟悉的主题（如"EVA 讨论"、"动画推荐偏好"、"对京阿尼的评价"），每个主题准备 2-3 个有内在关联的对话轮次：

```
Session 1（3天前）
  User: "我最近喜欢看意识流的动画，EVA 和玲音都看了"
  Agent: [回复，包含对意识流的看法]
  → 写入 L2 记忆

Session 2（今天）
  User: "推荐几部动画给我"  ← 期望：基于 Session 1 的偏好推荐
  → 召回应该命中 Session 1 的记忆
```

评测指标：

| 指标 | 定义 | 计算方式 |
|------|------|---------|
| **召回命中率** | 相关的前序会话是否出现在 top-5 召回结果中 | 人工标注"应该召回哪些会话"，对比实际召回列表 |
| **记忆使用率** | L2 召回的记忆是否被 agent 实际引用到回复中 | 检查 agent 回复是否包含来自 L2 记忆的个性化信息 |

### 2.3 A/B 测试：L2 注入 vs 关闭

对同一组 10 个场景（用户已有历史会话），对比：

| 条件 | 回复评价标准 |
|------|------------|
| L2 开启 | 回复是否体现了对用户历史偏好的了解？个性化程度（1-5） |
| L2 关闭 | 回复是否更通用/模板化？ |

用 LLM-as-Judge 评判个性化程度。如果 L2 开启的回复个性化评分显著高于关闭，则 L2 有效。

## 三、评测数据需求

### 3.1 L1 评测

- 1 个 10 轮对话脚本（见上文 1.2），带 5 个验证埋点和正确答案
- 不需要额外的 ground truth 标注——答案是确定的（"三月的狮子" 就是 "三月的狮子"）

### 3.2 L2 评测

- 3 个主题，每个 2-3 个关联会话 = 6-9 个会话
- 需要手动运行这些会话并确保 L2 写入成功
- **前提**: 数据库中有已写入的 L2 记忆。如果当前 `session_memories` 表为空，需要先跑几轮对话产生数据

### 3.3 注意事项

- L2 评测依赖数据库状态。建议在评测前 `pg_dump` 保存当前 `session_memories` 快照，评测完后恢复，保证可复现
- L2 写入是 fire-and-forget 的异步操作，评测时需要确认写入已完成后才开始召回实验

## 四、指标汇总

| 层级 | 指标 | 目标 | 当前已知 |
|------|------|------|---------|
| L1 | 10 轮信息保留得分 | auto 模式 ≥ 6/10 | E8 场景 0/1（第 8 轮失忆） |
| L1 | 压缩前后回答质量比 | ≥ 80% | 未知 |
| L2 | 召回命中率 | ≥ 60%（5 次命中 3 次） | 未知 |
| L2 | 个性化评分（L2 on vs off） | L2 on 显著高于 off | 未知 |

## 五、与简历的对应

做完 L1/L2 评测后，记忆系统的简历 bullet 从：

> "L1 短记忆——当前轮工具结果完整保留、上一轮提取关键字段压缩（~2000 → ~80 tokens）、更早轮次丢弃。L2 跨会话记忆——时间衰减 + 双通道语义召回"

变成：

> "L1 短记忆——三级压缩策略在 96% 压缩率下保持回答质量无明显退化（压缩后信息完整性评分 ≥ 完整上下文的 X%）。L2 跨会话记忆——时间衰减+双通道召回命中率 XX%，A/B 测试证明 L2 注入使回复个性化评分从 X 提升至 Y"
