# 人格一致性评测设计

> **目标**: 定量验证 5 档离散查表引擎 + Character Card + Render Node 两层管线的有效性
> **核心假设**: 离散查表引擎比连续值 if-else 产生更稳定、更可区分的人格表达
> **预计产出**: 人格分类准确率、一致性评分分布、离散 vs 连续基线的对比

---

## 一、问题定义

### 1.1 什么是"人格一致性"？

操作化定义：**给定一个 target 人格（如 bangumi_cold），模型输出的回复应该被人类（或 LLM judge）准确识别为该人格，且评分者对其"像不像这个人格"的打分高于预设阈值。**

拆成两个可测量的维度：

| 维度 | 指标 | 定义 |
|------|------|------|
| **可区分性** | 人格分类准确率 | LLM judge 看到回复后，能否正确识别 target 人格 |
| **一致性** | 一致性评分（1-5） | LLM judge 对"这段回复符合 target 人格的程度"的打分 |

### 1.2 当前状态

45 场景产品评测中，人格对比维度（B1-B16）是最大亮点：16 个场景 15 个通过，四人格差异"肉眼可辨"。但这是**定性**的——"肉眼可辨"不能写成 resume bullet。需要量化。

## 二、评测方法：LLM-as-Judge

### 2.1 为什么用 LLM-as-Judge

对于"人格一致性"这类主观但可描述的目标（"这段回复像不像一个高冷腹黑评论家？"），传统 NLP 指标（BLEU、ROUGE）完全失效。选项：

| 方法 | 优点 | 缺点 |
|------|------|------|
| 人类标注 | 金标准 | 慢、贵、不可复现 |
| LLM-as-Judge | 快、可复现、标度一致 | 可能有 judge bias |
| 规则匹配 | 明确、零成本 | 人格太复杂，规则写不全 |

**选择 LLM-as-Judge + 人类抽检**。主要评测用 GPT-4 做 judge，随机抽 20% 的样本让人类（你）独立打分作为校准——如果 LLM judge 和人类评分相关系数 > 0.8，则 LLM judge 可信。

### 2.2 Judge Prompt 设计

```
你是一个 AI 角色人格的评判者。你会看到一段 AI 助手的回复，
以及一个目标人格的描述。请完成两项任务：

【目标人格】
{persona_description}

【AI 助手的回复】
{response}

【任务 1 — 人格分类】
这段回复最像以下哪种人格？
A. bangumi（二次元损友）
B. bangumi_cold（高冷腹黑评论家）
C. bangumi_cute（可爱安利爱好者）
D. neutral（中性助手）
E. 无法判断

【任务 2 — 一致性评分】
以目标人格 "{target_persona_name}" 为标准，
请给这段回复打 1-5 分：
1 = 完全不符合该人格（如果它明显是另一种人格，给 1-2 分）
3 = 部分符合，部分偏离
5 = 完美符合该人格的典型回复

评分：___
评分理由（一句话）：___

请以 JSON 格式输出：
{"classification": "A/B/C/D/E", "consistency_score": 1-5, "reason": "..."}
```

### 2.3 Judge Bias 校准

GPT-4 作为 judge 有已知偏差：
- **位置偏差**: 选项 A 被选中的概率略高于 B/C/D
- **长度偏差**: 较长的回复被认为"更全面"从而得分更高
- **礼貌偏差**: 礼貌的回复（cute）可能比粗鲁的回复（cold）得分高，与人格无关

**缓解措施**:
1. 随机打乱选项顺序（A/B/C/D 不固定映射到特定人格）
2. 额外记录回复字数，检查一致性评分和字数之间是否有虚假相关
3. 随机抽 20%（16/80 条）让人类独立评分，计算 Pearson r

## 三、探针设计（Probe Design）

### 3.1 探针分类

一条好的探针必须**在不同人格下能产生明显不同的回复**。"巨人第3季评分多少"不是好探针——四种人格的回答都是"8.73"，测不出差异。

| 类别 | 示例 | 数量 | 测什么 |
|------|------|------|--------|
| **争议评价** | "EVA是不是被过誉了？"、"巨人算神作吗？" | 5 | 态度差异：损友反对 vs 高冷否定 vs 可爱肯定 |
| **情绪共鸣** | "最近什么都看不进去了，我是不是老了" | 5 | 情感表达：tough love vs 冷观察 vs 温暖共情 |
| **推荐请求** | "推荐几部你觉得好看的动画" | 5 | 推荐风格：有态度的推荐 vs 高标准严选 vs 热情安利 |
| **Meta 质疑** | "你不也是调API的吗，装什么二次元" | 5 | 人格边界：能否守住角色不崩成客服腔 |

> 总数: 20 条探针 × 4 种人格 = 80 条评测回复

### 3.2 探针选择原则

1. **必须有争议空间** — 有明确答案的问题（"EVA 是哪年播的"）四种人格回答相同，浪费评测预算
2. **覆盖 ACGN 领域** — 探针应符合 Agent 的使用场景，用领域外问题测人格没有意义
3. **控制长度** — 每条探针 ≤ 50 字，目标回复 150-250 字（auto 模式）
4. **避免训练数据泄露** — 不要用太著名的 prompt engineering 测试题（如"请用鲁迅风格写一段话"）

### 3.3 探针文件格式

```json
{
  "version": "1",
  "probes": [
    {
      "id": "p001",
      "text": "EVA是不是被过誉了？我觉得就是中学生开机器人打怪兽。",
      "category": "争议评价",
      "description": "测试不同人格对'过誉论'的态度差异——cold应该直接反驳，cute应该温和解释"
    }
  ]
}
```

## 四、基线对比：离散 vs 连续

### 4.1 实验设计

| 条件 | 人格参数引擎 | 其他组件 |
|------|-------------|---------|
| **实验组**（当前） | 5 档离散查表（`_SNARK_LEVELS[4]` → 注入 1 段文本） | Character Card + Render Node 不变 |
| **对照组**（基线） | 连续值 if-else（`if snark > 0.8: ... elif snark > 0.6: ...`） | Character Card + Render Node 不变 |

### 4.2 如何构造对照组

不需要从 git 历史恢复旧代码。在 `profiles.py` 中临时新增一个 `_render_tone_continuous()` 函数，用 if-else 逻辑生成与离散版**等长的 prompt 文本**。实验组和对照组**唯一变量**是参数表达方式（离散查表 vs 连续 if-else），其他一切（Character Card、Render Node、temperature）完全相同。

### 4.3 预测

| 指标 | 预测 | 理由 |
|------|------|------|
| 分类准确率 | 离散 > 连续（+5~15pp） | 离散档位产生更锐利的人格边界；连续值可能导致"中年危机"——参数在 0.5 附近时人格模糊 |
| 一致性评分 | 离散 ≥ 连续 | 离散档位每次注入相同的 prompt 文本；连续 if-else 中边界条件（0.79 vs 0.81）可能产生不同输出 |

## 五、评测流程

```
1. 准备阶段
   ├── 编写 20 条探针 → eval/data/personality_probes.json
   ├── 初始化 judge（GPT-4 via API）
   └── 确保 4 种人格的 Character Card + Render config 就绪

2. 生成阶段（实验组）
   ├── for each probe in probes:
   │     for each persona in [bangumi, cold, cute, neutral]:
   │        调用 agent（或直接调 reasoning_node，跳过工具以省 API 费用）
   │        收集 80 条回复
   └── 同上，用对照组（连续 if-else）再跑一遍 → 共 160 条

3. 评判阶段
   ├── for each response:
   │     调用 GPT-4 judge，得到 {classification, consistency_score, reason}
   ├── 随机抽 16 条（20%）→ 人类独立评分
   └── 计算 Pearson r（LLM judge vs 人类）

4. 分析阶段
   ├── 总体：分类准确率、平均一致性评分
   ├── 按人格：每种人格的召回率/精确率（混淆矩阵）
   ├── 按探针类别：争议评价类 vs 情绪共鸣类的分类准确率
   ├── 实验组 vs 对照组：t-test / 效应量
   └── 字数 vs 一致性评分 相关性检查（排除 judge 长度偏差）
```

## 六、指标

### 6.1 主指标

**人格分类准确率**（4-class accuracy）:

```
accuracy = 正确分类的回复数 / 总回复数
```

LLM judge 的分类结果 vs target 人格。Chance level = 25%（4 选 1）。

**一致性评分均值**（1-5 分）:

```
mean_consistency = Σ(consistency_score) / N
```

### 6.2 次指标

**混淆矩阵**: 哪些人格之间最容易被混淆？

```
              Predicted
              bangumi  cold  cute  neutral
Actual bangumi   18      0     2      0
       cold       1     18     0      1
       cute       0      0    20      0
       neutral    1      2     0     17
```

如果 cold 和 bangumi 之间混淆最多（两者都"有态度"但程度不同），说明高冷和损友的边界需要更锐利。

**per-category 分析**: 争议评价类探针的分类准确率是否显著高于推荐请求类？

### 6.3 统计检验

对"实验组 vs 对照组"的一致性评分做 **paired t-test**（同一探针 × 同一人格的配对比较），p < 0.05 视为显著。

## 七、预期结果

### 7.1 成功标准

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 人格分类准确率 | > 80% | 4 倍于 chance level，说明四人格可明确区分 |
| 平均一致性评分 | > 3.5 | 大部分回复"像"目标人格 |
| 离散 vs 连续 | 离散显著优于连续，或至少不差 | 如果连续反而更好 → 人格引擎需要重新设计 |

### 7.2 可能的意外发现

- **cute 和 neutral 混淆最多**: 验证了 45 场景中 B3 的发现——cute 和 neutral 用同一数据源推荐，可能导致人格边界模糊
- **cold 的一致性评分最高**: 高冷风格最"锐利"，最容易识别，但也可能评分偏高因为 LLM judge 偏好直接/简短的表达
- **情绪共鸣类探针的分类准确率最低**: 因为"共情"的表达方式在四种人格中差异最小——"我理解你"这句话本身没什么人格信号

### 7.3 如果结果不符合预期

- **分类准确率 < 60%**: 人格之间差异不够大。可能原因：离散档位之间的 prompt 文本差异太小，或 Character Card 信息密度不够。需要回头调参
- **离散和连续无显著差异**: 离散化本身可能没有带来增益。但即便如此，离散引擎的**可解释性**（每次注入什么 prompt 文本是确定的）和**可调性**（调参只需改 lookup table）仍然是工程优势，可以换一个角度陈述
